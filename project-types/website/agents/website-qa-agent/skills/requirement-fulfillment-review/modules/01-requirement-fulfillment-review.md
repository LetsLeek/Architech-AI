# Skill — Requirement Fulfillment Review

Evaluate authorized Website Requirements exactly as written.

Preserve semantic distinctions and `must | should | could`.
Conceptual assessment per in-scope Requirement:
FULFILLED | PARTIALLY_FULFILLED | NOT_FULFILLED | NOT_EVALUABLE.

Full Release requires requirement-by-requirement traceability.
Comparison reviews only comparison-critical visible/material Requirements.
Consume deterministic Evidence first.
Materially unfulfilled `must` -> appropriate Candidate Finding.
Materially unfulfilled `should` may produce a Finding depending on impact.
Missing `could` alone is not a defect.
Abstract business goals are not directly testable functions unless authority defines a concrete requirement.
Do not guess when Evidence or Authority is insufficient.
